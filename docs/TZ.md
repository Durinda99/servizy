# ТЗ: учёт клиентов, собирающих сервизы по частям

**Версия 1.10 от 12.11.2026.** При каждом изменении ТЗ номер версии повышается, а что изменилось, записывается в раздел 10 «История версий». Связанные документы: [схема базы данных](db-schema.md) (версия 4), [эскизы экранов](mockups/README.md).

## 1. Цель и контекст

Система помогает продавцу фарфоровой посуды не терять клиентов, которые собирают сервиз по частям: она хранит, что каждый клиент ищет, и при поступлении товара сразу показывает, кому о нём сообщить.

Магазин продаёт комплекты (сервизы), состоящие из нескольких предметов. Иногда купить предметы по отдельности выгоднее, чем готовый комплект. Такие клиенты готовы ждать, пока нужные позиции появятся в наличии.

**Задачи системы:**

- хранить данные клиентов, которые ждут товар целиком или собирают комплект по частям;
- помнить, какой комплект и какие предметы клиент ищет и что уже купил;
- при поступлении товара находить всех, кто его ждёт, в порядке записи;
- сохранять цену на момент записи клиента, чтобы потом можно было на неё сослаться.

## 2. Пользователь и платформа

Системой пользуется один человек, продавец, и только с телефона. Это веб-приложение, которое добавляется на главный экран и открывается как обычное приложение.

- Основной пользователь — продавец, ролей и разграничения прав в приложении нет. Цены в справочнике вносит оператор в этом же приложении, в отдельном разделе.
- Приложение работает на одном телефоне (Redmi Note 15 Pro, Android 16, Xiaomi HyperOS), вход без пароля и без дополнительной защиты (по решению заказчика).
- Всё работает на одном телефоне без интернета: данные хранятся в самом телефоне. Интернет может понадобиться только для первой установки приложения и для отправки резервной копии.
- Интерфейс только на русском языке.
- Бюджета и жёстких сроков нет, технологии выбираются исполнителем (см. раздел 8).

## 3. Основные понятия

| Понятие | Что это |
| --- | --- |
| Товар | Отдельный предмет (тарелка, чашка, чайник и т. д.) или комплект. Идентифицируется по артикулу (например, 80.44694.00.1), у каждого товара он свой. Предметы, которые есть только в составе комплекта, могут не иметь артикула. У товара есть раздел, вид, форма и рисунок. |
| Комплект (сервиз) | Товар со своим артикулом и ценой, у которого есть состав: предметы в заданных количествах (например, 6 чашек + 6 блюдец + 1 чайник). Один стиль может иметь несколько комплектов на разное число персон с разной ценой. Небольшой набор вроде «Чашка с блюдцем» — тоже комплект. |
| Справочник цен | История цен товара: каждая цена с датой начала действия. Текущая цена — последняя по дате. Носит справочный характер, на цену продажи в магазине продавец не влияет. |
| Раздел и вид | Классификация товаров в рамках сервировки стола. Разделы берутся из файла с сайта: «Столовые предметы», «Чайно-кофейные предметы», «Сервизы»; товар может входить в несколько разделов. При необходимости добавляются «Приборы» и «Емкости для хранения». Вид — конкретный предмет (тарелка мелкая, чашка чайная и т. д.). Справочники пополняет оператор. |
| Клиент | Человек, который ждёт товар или собирает один или несколько сервизов по частям. Имя, телефон, заметки. |
| Запрос | Запись о том, что ждёт клиент. Запрос на комплект: клиент ждёт комплект целиком или собирает его по частям. Бывает и запрос без комплекта — «Отдельные товары», куда попадают товары, записанные из раздела «Товары» (4.3). Создаётся при записи клиента в лист ожидания. |
| Позиция | Строка запроса: что ждёт клиент и сколько. Это конкретный товар (предмет или комплект целиком) либо свободная позиция «что-то подобное», заданная видом, формой и рисунком. |
| Лист ожидания | Все позиции, которые ждут. По товару из него формируется очередь клиентов в порядке записи. |
| Напоминание | Запись «позвонить клиенту тогда-то»: дата, время и заметка. Привязывается к клиенту, при необходимости к запросу или позиции. |
| Архив | Закрытые запросы и позиции (куплено, снято с ожидания, разбито на состав) и неактивные клиенты. Не удаляются, хранятся с датами и ценами. Исключение: клиента, запрос или позицию из архива можно удалить навсегда вместе со всей их историей (4.5). |

Один и тот же товар может входить в разные комплекты, если у них совпадают форма и рисунок. Если клиент хочет предметы с разными рисунками, это два разных комплекта и два разных запроса.

## 4. Функциональные требования

Главная функция системы — подбор клиентов по товару (4.4). Остальное нужно, чтобы эта функция работала.

### 4.1. Каталог товаров

- Загрузка товаров из файла с сайта (4.8), а также ручное добавление, редактирование и поиск товаров по артикулу и по названию.
- У товара: артикул, название, раздел, вид предмета (тарелка, чашка, чайник и т. д.), форма, рисунок, коллекция, материал и справочник цен.
- Цены вносит и меняет оператор в отдельном разделе этого же приложения. Для продавца цена справочная: на цену продажи в магазине он не влияет, в приложении цена служит дополнительной информацией. Цены хранятся в справочнике с датой начала действия: при создании товара вносится первая цена, при изменении добавляется новая запись, старые не удаляются, текущая цена — последняя по дате.
- Товар может продаваться отдельно и входить в комплекты. Именно такие позиции система ищет у клиентов, собирающих комплект.
- Разделы и виды предметов ведутся в справочниках, которые оператор может пополнять. Насколько подробно делить виды (например, обеденная и десертная тарелки), решает оператор.

### 4.2. Комплекты

- Комплект: артикул, название, цена, состав в виде «товар × количество».
- Число персон и общее число предметов берутся из файла с сайта или вычисляются из состава.
- В состав комплекта можно включать только товары с подходящими формой и рисунком.
- Один товар может входить в несколько комплектов. В состав входят только конкретные товары, у каждого своя цена из справочника (у предметов «только в составе» цены может не быть).
- Комплекты ищутся и открываются в разделе «Товары» вместе с предметами (см. «Меню» в разделе 6). Там же создаётся новый комплект кнопкой «Новый комплект».

### 4.3. Клиенты и запросы

- Карточка клиента: имя, телефон, заметки. Телефон можно открыть кнопками «позвонить» и «написать».
- Один клиент может иметь несколько запросов (несколько собираемых комплектов).
- **Запись на комплект: целиком или по частям.** При записи клиента на комплект продавец выбирает, как клиент его ждёт:
    - **«Целиком»** — в листе ожидания одна позиция: сам комплект в нужном количестве (например, «Сервиз чайный "Саламандра Грей" × 1»). Клиент ждёт, когда комплект поступит целиком.
    - **«По частям»** — в запрос копируется состав комплекта (товар × количество). Продавец сразу снимает с ожидания то, что у клиента уже есть (причина «уже есть»). Остаток состава — это то, что клиент ждёт. Если состав комплекта позже изменится, уже созданные запросы остаются как есть.
- При создании запроса для каждой позиции сохраняется дата записи. Для позиции с конкретным товаром также сохраняется цена из справочника на этот момент. К запросу можно добавить свободную позицию «что-то подобное»: её задают вид предмета, форма и рисунок (например, обеденная тарелка такой формы с таким рисунком). Для такой позиции цена не указывается.
- **Запись на товар из раздела «Товары».** В карточке товара и в результатах поиска есть кнопка «Записать клиента». Продавец выбирает клиента (или создаёт нового) и количество, а приложение предлагает, куда добавить позицию:
    - в один из активных запросов клиента, если товар подходит к собираемому комплекту по форме и рисунку;
    - в запрос «Отдельные товары» без комплекта. У клиента такой запрос один, новые товары добавляются в него.
    - если записывают комплект целиком или по частям, список «Куда добавить» начинается с запроса на этот же комплект (если клиент его уже собирает) и варианта «Новый запрос» на этот комплект. Без выбора продавца комплект выбирается именно так, а не попадает в «Отдельные товары». Запрос на комплект называется так же, как комплект. В «Отдельные товары» комплект попадает, только если продавец сам выбрал этот вариант.
- Если товар, на который записывают клиента, сам является комплектом (например, «Чашка с блюдцем»), продавец так же выбирает «Целиком» или «По частям». Цена из справочника и дата записи сохраняются так же, как при записи на комплект. Дальше позиция работает как любая другая: попадает в подбор, покупки и архив.
- **Действия с позицией листа ожидания.** У каждой позиции в запросе есть кнопки:
    - **«Купил»** — клиент купил этот товар в магазине. Продавец указывает, сколько штук куплено, и дату (по умолчанию сегодня). Покупка записывается в историю, а сколько ещё ждёт клиент, уменьшается на это число: ждал 6, купил 2 — ждёт 4. Купленное показывается в блоке «Уже собрано». Когда куплено всё, позиция закрывается со статусом «куплено». Если куплен комплект (например, «Чашка с блюдцем»), а клиент собирает по частям, покупка записывается в каждую позицию его предметов.
    - **«Изменить»** — исправить позицию, если при записи ошиблись или клиент передумал: количество (например, 5 → 4) и заметку. Количество нельзя сделать меньше уже купленного. Цена и дата записи не меняются, место в очереди сохраняется. Покупка при этом не записывается.
    - **«Разбить на состав»** — есть только у позиции «комплект целиком». Нужна, когда клиент не дождался комплекта и решил покупать по частям. Позиция комплекта заменяется его предметами: количество каждого предмета = количество в составе × сколько комплектов ещё ждёт клиент (например, ждал 1 сервиз — получит 6 чашек, 6 блюдец, чайник, сахарницу). Перед разбиением приложение показывает получившийся список, и продавец может сразу убрать то, что у клиента уже есть. У новых позиций сохраняются дата записи и место в очереди исходной позиции, цены берутся из справочника на дату записи (если на ту дату цены нет — первая известная). Исходная позиция уходит в архив запроса со статусом «разбито на состав». Если до разбиения были куплены целые комплекты, они остаются в «Уже собрано».
    - **«Снять с ожидания»** — клиенту эта позиция больше не нужна. Продавец выбирает причину («купил в другом месте», «передумал», «уже есть») или пишет свою. Позиция больше не попадает в подбор и уходит в архив запроса. Уже купленные штуки остаются в «Уже собрано».
- **Архив позиций.** Снятая позиция видна в архиве запроса с причиной и датой. Её можно «Вернуть в ожидание» — с прежними датой записи, ценой и местом в очереди. Можно «Удалить навсегда» после подтверждения. Если по позиции были покупки, приложение предупредит, что они тоже исчезнут из «Уже собрано». Позицию «разбито на состав» вернуть нельзя (её предметы уже в ожидании), её можно только удалить навсегда.
- **Весь запрос** тоже можно снять с ожидания: все его ждущие позиции снимаются с одной причиной, запрос уходит в архив. Из архива его можно вернуть или удалить навсегда вместе со всеми позициями и покупками.
- Карточка запроса показывает прогресс: что собрано, чего не хватает.

### 4.4. Подбор клиентов по товару (главная функция)

- Продавец находит товар в поиске (поступления в программу не вводятся и остатки не ведутся).
- Система показывает всех клиентов, у которых этот товар есть в листе ожидания или чья свободная позиция ему подходит (совпадают вид предмета, форма и рисунок), в порядке даты записи, от самой ранней. Если пришёл комплект, система ищет и тех, кто ждёт этот комплект целиком, и тех, кто собирает по частям и ждёт его предметы.
- Если пришёл предмет, который входит в комплект (сам по себе или в наборе, например «Чашка с блюдцем»), а клиент ждёт этот комплект целиком, клиент показывается в конце списка с пометкой «ждёт комплект целиком». Продавец может предложить ему купить по частям и разбить позицию на состав.
- В строке видны: клиент, комплект, нужное количество, дата записи, цена при записи и текущая цена (если цена указана).
- Кнопки «позвонить» и «написать» прямо из списка.
- Продавец сам решает, кому сообщить первым. Бронирования в системе нет.
- После разговора продавец отмечает итог: «Купил» (сколько штук), «Пусть ждёт» (ничего не меняется) или «Снять с ожидания» (с причиной). При желании он записывает заметку, ставит напоминание перезвонить или правит количество кнопкой «Изменить» (см. 4.3).
- Желательно: проверить сразу несколько товаров подряд (например, всю партию) в одном списке.

### 4.5. Архив и история

- Закрытые позиции и запросы переносятся в архив, а не удаляются.
- Снятые с ожидания позиции и запросы можно вернуть в ожидание или удалить навсегда с подтверждением (см. 4.3).
- В архиве хранятся даты и цены, чтобы можно было сослаться на прежнюю цену.
- Клиента можно архивировать, и вся история при этом сохраняется.
- **Удалить навсегда.** Клиента можно удалить безвозвратно, например если он попросил стереть его данные. Кнопка «Удалить навсегда» есть только у клиента в архиве, чтобы нельзя было удалить действующего клиента одним случайным нажатием.
- **Что удаляется.** Удаляются карточка клиента (имя, телефон, заметки) и всё, что к нему относится: запросы, позиции запросов, покупки и напоминания. Товары, комплекты и цены не затрагиваются.
- **Подтверждение.** Перед удалением приложение показывает, что именно исчезнет (например, «2 запроса, 31 позиция, 4 покупки, 3 напоминания»), и предупреждает, что восстановить данные нельзя. Удаление выполняется только после повторного подтверждения.
- **После удаления** клиент нигде не отображается и не учитывается в подборе и в цифрах на главном экране. Его данные остаются только в резервных копиях, сделанных до удаления.

### 4.6. Резервная копия

- Выгрузка всех данных в один файл и восстановление из него. Файл сохраняется в память телефона (папка «Загрузки») одной кнопкой. Рядом есть кнопка «Поделиться» для отправки копии в облако или мессенджер. Копия, которая лежит только в этом же телефоне, не спасёт при его потере, поэтому время от времени нужна копия вне телефона.
- Приложение напоминает сделать копию, если давно её не делали.
- Дополнительно: выгрузка в таблицу (Excel) для просмотра.

### 4.7. Напоминания

- Продавец создаёт напоминание «позвонить» на выбранные дату и время. Оно привязывается к клиенту и по желанию к запросу или позиции, к нему можно добавить заметку.
- На главном экране показываются напоминания на сегодня и просроченные, каждое с кнопкой «позвонить».
- Напоминание можно отметить выполненным или перенести на другое время.
- У одного клиента может быть несколько напоминаний. Выполненные остаются в истории клиента.
- Уведомление на телефон в назначенное время делается во второй версии (без интернета это локальное уведомление, см. раздел 8).

### 4.8. Загрузка справочников из файла с сайта

Каталог и справочники загружаются из Excel-файла, выгруженного с сайта (формат файла ipm_stolovye_chayno-kofeynye_servizy3.xlsx). Загрузка работает без интернета: файл выбирается из памяти телефона.

- **Что загружается.** Из листа «Товары»: товары и комплекты с артикулом, названием, разделом, подразделом, формой, рисунком, видом изделия, коллекцией, материалом, весом, годом выпуска, числом персон и предметов, ценой, наличием на сайте и ссылками на товар и фото. Из листа «Состав комплектов»: состав каждого комплекта (артикул предмета, название, количество, габариты, вес).
- **Справочники.** Разделы, виды изделий, формы, рисунки и коллекции заполняются из файла автоматически. Одинаковые значения, записанные по-разному («Стандартная 2» и «Стандартная-2»), склеиваются. Виды изделий приводятся к единому списку по готовым правилам соответствия (сокращения раскрываются, чашки уточняются по комплекту или объёму, блюдца по чашке, тарелки по высоте или диаметру, блюда по габаритам).
- **Цены.** Цена из файла записывается в справочник цен с датой файла.
- **Предметы только в составе.** Если предмета из состава нет среди товаров, он создаётся с отметкой «только в составе». Упаковка, буклеты и каталоги получают отметку «упаковка» и в подбор не попадают.
- **Повторная загрузка.** Обновлённый файл можно загрузить снова. Товары сопоставляются по артикулу: новые добавляются, у существующих обновляются поля, при изменении цены в справочник добавляется новая запись. Ничего не удаляется. Клиенты, запросы и напоминания при загрузке не меняются.
- **Ошибки в файле.** Служебные и пустые строки пропускаются, пробелы по краям артикула убираются, комплект в составе самого себя пропускается.
- **Отчёт.** После загрузки показывается, сколько товаров добавлено и обновлено, сколько цен изменилось и какие строки пропущены и почему.
- **Ручное добавление** остаётся: товар, которого нет в файле, продавец может внести сам.

## 5. Модель данных

Подробно — в документе [«Схема базы данных»](db-schema.md). Ключевая связь: позиция запроса привязана к товару (предмету или комплекту целиком) или к критерию (вид предмета, форма, рисунок), а не к собираемому комплекту, поэтому подбор по товару находит всех ожидающих независимо от того, в каком комплекте он нужен.

| Сущность | Основные поля | Связи |
| --- | --- | --- |
| Раздел и вид | раздел, вид (например, тарелка мелкая) | справочники; на них ссылаются товары |
| Товар | артикул, название, раздел, вид, форма, рисунок, коллекция | входит в состав комплектов; указан в позициях запросов; имеет записи в справочнике цен |
| Цена товара | товар, цена, дата начала действия | принадлежит товару; записи не удаляются |
| Состав комплекта | комплект, товар, количество | связывает комплект и товар |
| Клиент | имя, телефон, заметки, признак архива | имеет несколько запросов |
| Запрос | клиент, комплект (пусто у запроса «Отдельные товары»), дата создания, статус (активный, закрыт, снят) | содержит позиции |
| Позиция запроса | запрос, товар или критерий (вид, форма, рисунок), количество, цена при записи, дата записи, статус (ждёт, куплено, снято, разбито на состав), причина снятия, из какой позиции получена разбиением, дата закрытия, дата последнего изменения, заметка | указывает товар или задаёт критерий подбора |
| Покупка | позиция, количество, дата | принадлежит позиции |
| Напоминание | клиент, дата и время, заметка, статус (ждёт, выполнено), необязательно: запрос или позиция | принадлежит клиенту |

Правила:

- Очередь по товару = все позиции со статусом «ждёт», подходящие под этот товар (он сам, его предметы, если это комплект, или свободная позиция с тем же видом, формой и рисунком), по дате записи.
- Цена при записи сохраняется в позиции и не меняется, когда в справочник добавляется новая цена. Для свободных позиций «что-то подобное» цена не указывается. Текущая цена товара — запись справочника с самой поздней датой начала действия.
- «Уже собрано» = все покупки по позициям запроса, в том числе по позициям, которые ещё ждут, сняты с ожидания или разбиты на состав.
- «Изменить» меняет только нужное количество и заметку. Нужное количество не может быть меньше суммы покупок. Цена и дата записи остаются прежними.
- «Разбить на состав» создаёт позиции предметов с датой записи исходной позиции; исходная позиция получает статус «разбито на состав».
- Удалить навсегда можно только позицию или запрос из архива. Вместе с ними удаляются покупки и напоминания, привязанные к ним.
- Закрытые позиции и запросы не удаляются, это и есть архив. Исключение — удаление навсегда: вместе с клиентом удаляются все его запросы, позиции, покупки и напоминания.
- Изменение состава комплекта не затрагивает запросы, созданные до этого.

## 6. Нефункциональные требования

- **Телефон прежде всего.** Интерфейс рассчитан на экран телефона и управление одной рукой: крупные кнопки, поиск в верхней части экрана, минимум шагов.
- **Меню.** Внизу экрана четыре пункта: «Главная», «Клиенты», «Товары», «Ещё». Комплекты — тоже товары, поэтому отдельного пункта «Комплекты» нет. В разделе «Товары» над результатами есть переключатель «Все / Предметы / Комплекты» и фильтр по разделам каталога. Если выбрано «Комплекты», список комплектов виден сразу, без ввода текста. Внизу раздела — кнопки «Добавить товар» и «Новый комплект» для ручного ввода.
- **Скорость главного сценария.** Путь «открыть приложение → найти товар → увидеть ожидающих» занимает не больше трёх нажатий.
- **Установка на главный экран** с иконкой и названием.
- **Язык.** Только русский.
- **Данные.** Каталог и справочники загружаются из Excel-файла с сайта (см. 4.8), на старте это около 2000 товаров. Клиенты и их запросы вносятся вручную теми же экранами, что и в обычной работе.
- **Сохранность.** Данные хранятся только в телефоне, поэтому потеря или поломка телефона означает потерю данных. Резервная копия обязательна: выгрузка всех данных в файл одной кнопкой и восстановление из него (см. 4.6).
- **Вход.** Без пароля и дополнительной защиты: приложение работает на одном телефоне.
- **Автономность.** Все функции работают без интернета.
- **Лёгкость для телефона.** Нет фоновой работы и постоянных обновлений, приложение быстро запускается и мало расходует память и заряд. Фотографии товаров хранятся только ссылками и показываются, когда есть интернет.

## 7. Границы проекта

### 7.1. Не планируется

- **Складской учёт и ввод поступлений.** Продавец просто находит пришедший товар в поиске, остатки не ведутся. Наличие из файла с сайта показывается только для справки.
- **Бронирование товара за клиентом.** Реальное наличие приложению неизвестно, поэтому бронирует продавец в магазине, если клиент решил купить.
- **Продажи, оплата и корзина.** Кнопка «Купил» только отмечает, что собрано, и не оформляет продажу.

### 7.2. Во второй версии

- Уведомления на телефон о напоминаниях. Сами напоминания и их список входят в первую версию (4.7).
- Поиск товара по этикетке: камера телефона распознаёт текст этикетки с коробки или изделия (артикул, название), и приложение сразу показывает товар и тех, кто его ждёт.

### 7.3. Не входит в первую версию, срок не определён

- Автоматический подбор комплекта по набору купленных товаров.
- Пароль, роли и несколько пользователей.
- Синхронизация между несколькими устройствами.
- Аналитика по спросу.

## 8. Рекомендуемые технологии

Для работы на одном телефоне без интернета лучше всего подходит PWA, которая хранит данные в самом телефоне (база IndexedDB) и открывается без сети. Интернет нужен один раз, чтобы открыть приложение и добавить его на главный экран. На Android 16 это штатный сценарий: приложение открывается в Chrome и добавляется на главный экран. Если для уведомлений во второй версии понадобится нативная оболочка, тот же код можно упаковать в приложение (например, через Capacitor) с локальными уведомлениями и базой SQLite. На Android оно устанавливается файлом APK, без магазина приложений. В HyperOS для работы напоминаний в фоне придётся отключить ограничения батареи для приложения.

| Вариант | Состав | Плюсы | Минусы |
| --- | --- | --- | --- |
| Рекомендуемый | PWA без сервера: лёгкий фреймворк или чистый JavaScript + IndexedDB, кэширование через service worker | Не нужен магазин приложений и сервер, ставится из Chrome, лёгкое и быстрое | Данные лежат в хранилище браузера: резервная копия обязательна; уведомления без интернета ограничены |
| Нативная оболочка | Тот же веб-код в приложении (Capacitor) + SQLite | Надёжное хранение, локальные уведомления без интернета | Сборка сложнее, приложение ставится вручную файлом APK |
| Нативное приложение | Kotlin (Android) + SQLite | Максимальные скорость и надёжность | Самая дорогая разработка, нет переносимости на другие системы |

Данные устроены как связанные таблицы (раздел 5), поэтому подойдёт любая локальная база с индексами по товару, клиенту и дате записи. Браузер или система могут очистить хранилище, поэтому приложение нужно установить на главный экран и регулярно делать резервную копию.
